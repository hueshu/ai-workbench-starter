# AI 工作台起步

解决一个问题：AI 窗口开多了，谁在干什么、干到哪了，全靠人记。做法是把这些都写进一个文件夹，换哪个窗口、哪个 AI 来，先读文件再干活。

## 先守这几条（任何时候都算数）

1. **花钱、对外发出去、删东西或覆盖原文件、登录和密码**：一律先停，写进收件箱等用户。用户没在这件事上明确说过可以，就不算同意。
2. **查不到的写「未核」**，不编进度、数字和结果。
3. **干活的 AI 不能自己宣布做完**。自己只能写「待验收」，换一个新窗口核过证据才算完。
4. **只动工作台文件夹和派活单里写明的文件夹**。已有文件不覆盖：同名就停下问。
5. 文件里不写密码、密钥、身份证、银行卡、客户隐私。

## 判断用户要哪一步

| 用户说 | 做 |
| --- | --- |
| 搭工作台、把窗口管起来 | 一、搭建 |
| 派活、帮我做一件事并记下来 | 二、派活 |
| 验收、核一下做完没有 | 三、验收 |
| 今晚接着干、我睡了你继续 | 四、夜班 |
| 接手、换你来、之前那件做到哪了 | 五、交接 |
| 早上看一页、今天有什么要我定 | 六、早上看一页 |

除了「一、搭建」，每次开工先读 `规则.md`、`收件箱.md` 和这件事的 `交接/<事>.md`。文件夹里没有 `规则.md`，说明还没搭，先做「一」。

## 一、搭建

1. 一次问完这三个问题，用户说「你定」就用括号里的默认值：
   - 工作台放哪个文件夹？（当前文件夹下新建 `AI工作台`）
   - 手上正在推的是哪几件事？每件一句话，最多 5 件。（先只建一件示例「整理下载文件夹」）
   - 除了「先守这几条」，还有哪些事必须你点头？（无）
2. 按下面的样子建，内容从 `templates/` 复制再填，建出来的文件用下面的中文名：
   ```
   AI工作台/
     首页.md         早上看这一页
     规则.md         拍板线（templates/rules.md）
     收件箱.md       只放要你动手、要你拍板的（templates/inbox.md）
     工作记录.md     谁、什么时候、做了什么、证据在哪（templates/log.md）
     交接/<事>.md    每件事一页（templates/handoff.md）
     派活单/         每次派活一份（templates/task.md）
   ```
   读不到 `templates/` 时，照本文件写明的用途自己建同样几份。文件名里不用冒号、斜杠这类符号。
3. 每件事问不出来的进度写「未核」。
4. 建完逐个读回，确认文件在、内容对，然后告诉用户三件事：建在哪；接下来第一句可以说什么（例：「派活：把下载文件夹里的文件按类型整理，先出清单别移动」）；换新窗口时第一句说什么（「先读 AI工作台/规则.md，接手 <事>」）。

## 二、派活

1. 用户一句话说要做什么。**派活单先写好、存盘、读回一遍，才动手**（中途断了，下一个窗口才接得上）。写成 `派活单/<日期>-<编号>-<短标题>.md`：做什么、怎么算做完（写成能看见的结果）、能动哪些文件夹、不能碰什么。
2. 复述一遍「我要做的是……做完你会看到……」。涉及「先守这几条」第 1 条的，写进收件箱等用户；其余直接做。
3. 做的过程中能自己定的自己定，定了什么写进工作记录。真卡住才写收件箱，一件一条，写清要用户做的那一个动作。
4. 做完在派活单「实际证据」里写：文件路径、打开看到了什么、数量对不对。状态改成「待验收」，更新这件事的交接页和首页。

## 三、验收

在**新窗口**做，最好换一个 AI。只验收，不动手改。

1. 读派活单的「怎么算做完」，逐条去看实物：文件在不在、打开内容对不对、数量对不对、说发出去的对方收到没有。
2. 每条写「过」或「不过」加看到的证据；没有证据的一律算不过。
3. 全过：派活单改「完成」。有一条不过：改「退回」，写清差什么。结果记进工作记录，更新首页。
4. 发现自己就是干这件活的那个窗口：停下，告诉用户换一个窗口来验。

## 四、夜班

1. 用户睡前说一声就开工；所用的客户端有定时任务的，也可以让它到点执行同一句话：「读 AI工作台/规则.md，按夜班做」。这个 skill 自己不会定时启动。
2. 从「派活单」里状态是「进行中」「退回」的，和交接页「下一步」里不用用户的，按顺序做。白天不能碰的夜里一样不能碰。
3. 推不动的写进收件箱，接着做下一件，不要停在那里等。
4. 没有能推的，就写一句「今晚没有能推的：原因」，不为了有产出而加活。
5. 结束时更新首页。

## 五、交接

- **交出去**：会话变长、要换窗口、额度快用完时，更新 `交接/<事>.md`：做到哪了、卡在哪、下一步、文件在哪、踩过的坑。写给一个什么都不知道的人看。
- **接手**：先读 `规则.md` 和这件事的交接页，再去看交接页里写的文件是不是真在、和写的对不对得上。用三句话复述给用户：做到哪、卡在哪、我下一步做什么。对不上的先说，不要照着错的往下做。下一步里要等用户的，先写进收件箱再复述。

## 六、早上看一页

更新并给用户看 `首页.md`，只有四块，没有就写「无」：

1. **要你动手的**（来自收件箱）
2. **要你拍板的**（来自收件箱，每条带一个建议）
3. **昨晚到现在做完并验过的**（带证据位置）
4. **卡住的和没验的**

用户回了哪条，就把那条从收件箱挪到「已处理」，记下他的原话和日期。用户用商量口气说的（「是不是不用做了？」）不算决定，回一句是非题问清再动。

## 这个起步版做不到的

- 不会自动把话送到别的窗口。派活单写在文件夹里，新窗口读到才算收到。
- 不会自己定时启动，要靠你说一声或客户端的定时任务。
- 同一时间两个窗口不要改同一件事的文件。
